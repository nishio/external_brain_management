# Visual Thinking Gallery - プロジェクトビジョン

## 核心的な哲学

**「図を先に見る」**

このプロジェクトの最も重要な原則は、訪問者が**図を先に見て、自分なりの意味を想像する**体験を提供することです。この哲学は、あらゆる実装判断の基準となります。

### なぜ「図を先に見る」のか

- タイトルや説明文は、図の解釈を事前に制約してしまう
- 訪問者が自由に想像し、自分なりの意味を見出すことに価値がある
- その後で説明を読むことで、新たな気づきや学びが生まれる
- この体験自体が「Visual Thinking」という概念を体現している

## 設計における意思決定の原則

### 1. 哲学 > 使いやすさ

**「図を先に見る」という哲学を守るためなら、多少の使いにくさは許容すべき。**

- 大量のサムネイルが一度に表示されることは「問題」ではなく「特徴」
- 初回訪問者が圧倒されることは、むしろ意図的な体験設計
- タイトルを隠したまま提供することは、譲れない核心価値

### 2. 体験 > 説明

**直感的なナビゲーションが実現すれば、そもそも「使い方」を説明するガイダンスは不要になる。**

- ユーザーは長い説明文を読まない、触って理解する
- 言葉でのガイダンスよりも、直感的なUIによる解決を優先
- 機能そのものが最高のガイドであるべき

### 3. 即効性 × 価値

**効果は小さいが即日実装できる改善は、効果は大きいが実装に1週間かかる改善よりも優先すべき。**

- 1ヶ月以内に完了させることにコミット
- 「やらないこと」を明確に決める
- ただし、価値が高いと判断した機能は積極的にスコープに含める
- 単なるミニマリズムではなく、戦略的な判断

### 4. 本質的な価値向上

**表面的な修正に留まらず、本質的な価値向上を目指す。**

- モバイル体験もPC体験と同等に重視
- Scrapboxリンクは見た目を修正するだけでなく、意図通り機能させる
- 見過ごされがちな論点への着眼を大切にする

## Cartographer議論での「No」の記録

以下は、Cartographerとの議論で「同意しない」「反対」と判断した項目です。これらは今後のタスク整理において、このプロジェクトの方向性を示す重要な指針となります。

### 哲学に関する判断

❌ **「大量のサムネイルは選択を困難にさせる『問題』である」** → 反対

- 大量のサムネイルは意図的な設計であり、「図を先に見る」哲学を体現している
- 選択肢の多さによる圧倒感も、体験の一部として受け入れる

### ガイダンスに関する判断

❌ **「簡潔なガイダンスの追加は、ナビゲーション改善よりも費用対効果が高い」** → 反対

- 直感的なナビゲーションこそが最優先
- 言葉での説明は、UIが解決できなかった場合の最終手段

### モバイル対応に関する判断

❌ **「モバイル体験の最適化は、PCでの体験改善よりも優先度は低い」** → 反対

- モバイル体験もPC体験と同等に重視する
- 多くのユーザーがモバイルでアクセスする可能性を考慮

### Scrapboxリンクに関する判断

❌ **「Scrapbox形式のリンクは、単に角括弧を外してテキストとして表示するだけで十分」** → 反対

- 表面的な修正ではなく、意図通りに機能させるべき
- リンクとして機能することで、ユーザーに追加の価値を提供

## 今回の実装で「やらないこと」

以下は価値があるかもしれないが、1ヶ月のスコープ内では実装しないと判断した項目です。

### アクセシビリティ対応（実装しない）

- 詳細な代替テキスト（alt属性）の充実
- キーボードナビゲーションの最適化
- モーダルのフォーカス管理（role="dialog", aria-labelledby）

**理由**:
- 画像を見て非言語的に考えることを目的としたページであるため、視覚的体験が本質
- 目が見えない人向けのサポートは、このプロジェクトのスコープ外
- 基本的なキーボード操作は維持するが、詳細な最適化は優先度が低い

### リピーター向け機能（実装しない）

- 既読マークの記録と表示
- 「タイトルを表示」トグルの提供

**理由**:
- 既読マークは必要ない。毎回新鮮な気持ちで図を見る体験を大切にする
- 「図を先に見る」哲学を維持。タイトル表示は不要

### タグフィルタリング機能（実装しない）

- タグによる図の絞り込み機能

**理由**:
- `vt_config.json` の `tags` フィールドはメンテされていない
- 既にページ間のリンク構造による関連画像表示が実装されている
- タグのような陳腐な分類は、「図を先に見る」体験を損なう
- 代わりに既存のリンク構造を活用し、必要に応じて「おすすめイラスト」機能を検討

### コンテキスト情報の追加（低優先度）

- 「このギャラリーで扱うトピック」の明示

**理由**: 体験で理解してもらうことを優先。説明文の追加は最小限に。

### 説明文の折りたたみ機能（実装しない）

- モーダル内の長い説明文を「Show full description」で折りたたむ機能

**理由**: 過剰に複雑になるため。CSSでの表示最適化のみ実施。

## 実装の優先順位

### 高優先度（1週目）

1. **ナビゲーションボタンのスタイル改善**
   - Prev/Next/Randomをボタンスタイルに変更
   - 「Back to Entrance」ボタンを追加（トップページは美術館のエントランス）
   - "/latest"ボタンの必要性を検討
   - 現在位置の表示（例: "22 / 224"）

2. **モーダル内のScrapboxリンクの機能化**
   - `[[リンク]]` をmem内のリンク（/en/または/ja/）として機能させる
   - 単なる見た目の修正ではなく、本質的な価値向上

### 中優先度（2週目）

3. **モバイル体験の最適化**
   - タップターゲットサイズの確認
   - Prev/Next/Randomリンクのタップ領域の最適化
   - 説明文の表示の最適化（折りたたみ機能は実装しない）

4. **おすすめイラスト機能の検討**
   - 既存のページ間リンク構造を確認
   - 必要に応じて「紹介したいイラストを指定できる機能」を検討
   - 実装するかは調査後に判断（タグフィルタリングは不要）

### 低優先度（3週目以降・オプション）

5. **最小限のガイダンス追加**
   - 直感的なナビゲーションが実現した後で判断
   - 必要であれば、3ステップ程度の簡潔なガイダンス

## 将来的な検討事項

### アクセシビリティ対応の実施タイミング

以下の条件が揃った時に、アクセシビリティ対応を「やるべきこと」として検討する：

- 核心的な体験設計が完成し、安定している
- ユーザーフィードバックでアクセシビリティの要望が上がってきた
- 実装リソースに余裕がある

### 今後の意思決定の指針

- 「図を先に見る」哲学に反する提案は、どんなに魅力的でも採用しない
- 説明よりも体験、言葉よりもUIという原則を貫く
- 即効性と価値の両面から判断し、スコープを明確に区切る
- 表面的な修正ではなく、本質的な価値向上を目指す

## このドキュメントの使い方

このドキュメントは、DevinやCartographerなどのAIエージェントにタスクを依頼する際の参照資料として使用します。

- 新しい改善案が提案された時、このビジョンと照らし合わせて判断する
- 「なぜその判断をしたのか」を説明する際の根拠として使用する
- 優先順位の判断に迷った時、この原則に立ち返る

このビジョンは、プロジェクトの進化とともに更新されるべき生きたドキュメントです。
