### 3. skipped配列への追加（重要）

**問題点の指摘**:
ユーザーから「削除済みのものが再度追加されないようにdeleted的なものに記載されてるんじゃなかったっけ？記載し忘れてない？」との指摘。

**対応**:
削除した3つのページ名を`skipped`配列に追加することで、今後自動的にVT候補として検出されても再追加されないようにしました。

```json

  "#Ｚ世代的価値観",
  "'cy' is not defined",
  "01VERSE",
  "1%の革命",
  "トートバッグ",
```

**skipped配列の役割**:
- 管理画面の「Scan」機能やadd_from_add_new_vt.jsスクリプトが、Gyazo画像を含むページを自動検出する際にこのリストをチェック
- リストに含まれるページ名は候補から除外される
- 削除したページが今後再び自動追加されることを防ぐ

## 技術的な学び

### 1. データ整合性の管理

削除操作は単に`illusts`配列からエントリを削除するだけでは不十分：

1. **即時削除**: `illusts`配列からエントリを削除
2. **再発防止**: `skipped`配列にページ名を追加
3. **デプロイ**: Vercelに自動デプロイされて本番反映

### 2. skipped配列の設計思想

```javascript
// scripts/add_from_add_new_vt.js の例
const skippedPages = new Set(config.skipped || []);

illusts.forEach(item => {
  if (skippedPages.has(item.page_ja)) {
    console.log(`[SKIP] "${item.page_ja}" is in skipped list`);
    return;
  }
  // 追加処理...
});
```

- **Set**を使用して高速な検索（O(1)）
- ページ名（`page_ja`）をキーとして管理
- スクリプト実行時に自動的にフィルタリング

### 3. 段階的なコミット戦略

今回は以下の順序で実施：
1. ID 230を削除 → コミット → プッシュ
2. ID 237を削除 → コミット → プッシュ
3. ID 236を削除 → コミット → プッシュ
4. skipped配列を更新 → コミット → プッシュ

**改善案**:
- 削除とskipped追加を1つのコミットにまとめる方が効率的
- ただし、段階的な実施により問題の切り分けが容易になった

## 学んだこと

### 1. レビュープロセスの重要性
ユーザーからの「記載し忘れてない？」という指摘により、重要な手順（skipped配列への追加）を思い出すことができました。

**教訓**:
- 削除操作には必ず「再発防止」の手順を含める
- チェックリストを作成して漏れを防ぐ
- ユーザーフィードバックは貴重な品質改善の機会

### 2. データ管理の二重構造
- **illusts配列**: 現在表示するページのリスト
- **skipped配列**: 今後追加しないページのブラックリスト

この二重構造により、動的なコンテンツ管理と履歴管理を両立。

### 3. Git操作の注意点
```bash
# ❌ 間違い：cdせずにgit add
git add vt_config.json  # pathspec error

# ✅ 正しい：サブモジュールディレクトリに移動
cd /Users/nishio/external_brain_management/modules/mem
git add vt_config.json
```

サブモジュール内の作業では、必ずそのディレクトリに移動してからgitコマンドを実行。
