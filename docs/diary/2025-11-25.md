## Scrapbox即時同期のテスト

### 背景

Scrapboxで新しいページ「遅い自分はボトルネックだけど、それでも全体としては速く賢く動けている」を作成し、即時同期機能が正しく動作するか検証することになった。

### 発生した問題と解決

#### 問題1: "Argument list too long" エラー

**エラー内容**:
```bash
tasks/update_markdown/run.sh: line 41: /bin/cp: Argument list too long
```

**原因**: `cp -r quartzPages/* external_brain_in_markdown/pages/` コマンドで24,000+のファイル名をシェルが展開しようとして、システムのARG_MAX制限を超えた。

**解決策**: `cp` を `rsync` に変更
```bash
# 変更前
cp -r quartzPages/* external_brain_in_markdown/pages/

# 変更後
rsync -a --delete quartzPages/ external_brain_in_markdown/pages/
```

**rsyncのメリット**:
- シェルのグロブ展開を使わない（パス全体を扱う）
- `--delete` オプションで削除されたファイルも同期
- 大量ファイルの同期に適している

**編集したファイル**: `/modules/from_scrapbox/tasks/update_markdown/run.sh:41`

#### 問題2: Git push rejection

from_scrapboxで変更をpushしようとしたら、リモートに新しいコミット（Devinの作業）があり拒否された。

**解決**:
```bash
cd modules/from_scrapbox
git pull --rebase
git push
```

**コミット**: `9f92d70` - fix: use rsync instead of cp to avoid Argument list too long error
